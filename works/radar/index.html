AI 造物者雷达

Builder Radar — 一个不会停在采集那天的监测页。

我很喜欢一个开源的「博主动态监测页」：把某位 AI Builder 的推文、笔记、仓库整理成一页。 但它是把数据写死在 HTML 里的静态页——采集那天之后，页面就停在了那一刻。 我想要的是同一个体验，但数据自己会更新，而且不只盯一个人。

于是有了这版：监测 6 位 AI Builder 的 GitHub 公开动态，每 3 小时自动抓一次， 每次抓完和上一次快照做 diff，算出 star / follower 增量，再由 GitHub Pages 直接发布。 全程 0 服务器、0 成本、0 手工维护。

How it works · 实现

把「实时」拆成
四个便宜的动作

Cron, diff, commit, publish.

01

定时抓

GitHub Actions 每 3 小时跑一次 Python 脚本，用仓库自带的 GITHUB_TOKEN 调公开 API，额度 5000 次/小时，够用得离谱。

02

存快照

每次抓完把 stars / followers 存进 data/history/日期.json，天然形成时间序列——增量是算出来的，不是抓出来的。

03

自动提交

数据有变化才 commit，避免刷屏；页面只读一个 builders.json，前端不需要任何后端。

04

直接发布

GitHub Pages 托管，commit 完成即上线。挂了也不会白屏：读不到数据时显示上次快照与明确提示。

与静态原版的差别
维度静态原版这一版
数据时效停在采集当天每 3 小时自动更新
监测范围1 位博主6 位，加人只改配置数组
趋势只有当下数值快照 diff 出 Δ Stars / Δ Followers
维护成本手工重抓 + 手改 HTML0，Actions 自己跑
失败表现—降级展示上次快照并标注 stale

说明：X / 小红书没有稳定的公开接口，这版只用 GitHub 公开数据做实时部分，社媒仅保留跳转入口—— 宁可少一个指标，也不做「看起来实时」的假数据。

核心工作流（.github/workflows/update-radar.yml）
on: schedule: - cron: "17 */3 * * *" # 每 3 小时 workflow_dispatch: # 也能手动点一下 jobs: update: runs-on: ubuntu-latest permissions: { contents: write } steps: - uses: actions/checkout@v4 - run: python3 scripts/fetch_builders.py env: GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} - run: | git add data git diff --staged --quiet || \ git commit -m "更新雷达数据" git push
